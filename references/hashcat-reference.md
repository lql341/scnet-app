## Apply the benchmark without copying its boundaries

- The preferred single-skill pattern is an application entry point with a minimal,
  pinned OpenAPI adapter derived from scnet-hpc, as hashcat does. Keep a vendor
  manifest with upstream commit and checksums, reuse the shared credential store,
  and add an integrity test. Do not copy the full SSH/scheduler stack or create a
  second credential store.
- Calling an installed scnet-hpc CLI is an alternative for advanced first-use,
  SSH, deployment or diagnosis. Users should not have to load scnet-hpc as a
  second skill for the normal application workflow.
- Hashcat has an existing multi-node driver. The scnet-app v1 descriptor is
  single-node; referencing that driver does not add MPI, arrays or fan-out support.
  Hashcat was not generated by scnet-app and does not implement its app.json contract.
- Hashcat expects an existing compatible module. It does not establish a universal
  cluster installer or binary packaging standard. Follow the target site's actual
  deployment policy and the [integration requirements](cluster-integration.md).
- Use application-specific correctness: hashcat's synthetic recovery counts are
  not an acceptance criterion for a simulation or AI model. Runtime or multi-node
  evidence for hashcat cannot certify another application's hardware support.

Before publishing a new application, verify clean skill installation, document
remote deployment prerequisites, review its SCNet resource/Slurm plan, exercise
failure handling, and run its smallest meaningful compute-node correctness case.
Keep untested stages explicitly unverified.

## Mapping the benchmark into acceptance records

For the bundled single-node dictionary case, `report.json` provides `cracked`,
`total_hashes`, `expected_ranks`, `reported_ranks` and `ok`. A reviewed adaptation
can use numeric checks for `cracked == 5` and `total_hashes == 7`, plus a hook check
for `ok` and matching expected/reported ranks. Retain the raw rank/device logs,
summary and private run manifest, not only the counts. Counts are specific to this
synthetic case, not arbitrary user workloads. See [verification](verification.md).
This is an onboarding mapping, not a new app.json interface in scnet-hashcat or
new compute-node validation for scnet-app.
